# geo-sleuth 国内化改造说明

改造目标：**让 skill 在国内无代理环境下也能跑通主要流程**，同时保留用 Google / Overpass
时开代理的通路。

---

## 一、改造了什么

### 1. 新增 `scripts/netcheck.py` —— 先探网络，再干活

以前 agent 只能一个个命令试到超时（实测在不通的源上白等 8 分钟）。

```bash
uv run <skill>/scripts/netcheck.py
```

10 秒输出三段：直连源哪些通、需代理的源哪些通、以及**该怎么配代理**。
支持 `--json`（给 agent 解析）、`--proxy <地址>`（连代理一起测）、`--at lat,lon`。

它会**自动发现本机代理**：先查系统代理设置，再查环境变量，最后挨个试常见端口；
然后拿一个境外源当标尺**逐个实测**，筛出真正能连的那个。

### 2. `tiles.py`：默认源从 Google 改成国内自动回落

| 项 | 改前 | 改后 |
|---|---|---|
| 默认源 | `google`（国内不通） | `auto`：高德 → Esri → Google |
| 卫星源 | 仅 Google | 新增高德（免 key）、天地图（需 key） |
| 源失效时 | 静默出黑图 | 逐个回落，全失败时明确报错 + 排查指引 |
| 切片重试 | 无 | 每片重试 2 次 |
| `sheet` 子命令 | 硬编码 `SOURCES[...]` | 走 `_src_fmt()` + 源探测 |

### 3. `sat_scan.py`：源自动探测 + 模型多镜像回落

改前默认 `google`，国内会卡 8 分钟才失败。

- `_resolve_source()`：`auto` 时先用一张已知瓦片探源，选第一个通的
- 模型下载：逐镜像真下（hf-mirror → modelscope → 官方），失败自动换下一个
- 修了一个隐蔽 bug：`args._orig_source` 属性不存在会 AttributeError

### 4. 新增 `scripts/hf_sources.py` —— 模型下载源回落

解决国内下模型失败的两个根因（详见"踩坑记录"第 2 条）。

### 5. `gazetteer.py`：Overpass 不通时退到本地表

Overpass 一挂（国内无代理常见）整条命令就废。现在会捕获异常，直接用内置
`data/cn_admin.json` 列出下级行政区（无 bbox，但能把候选"列全"，这正是
skill 硬规则「类别推断先列全」需要的），并提示后续怎么补坐标。

### 6. 文档同步

- `SKILL.md` 升到 v3，新增「★ 第 0 步：先探网络」章节（放在流程最前，硬性要求）
- `references/data-sources.md` 新增「国内直连 vs 需要代理」对照表、代理配置步骤、
  卫星图瓦片口径踩坑记录

## 二、国内直连 vs 需要代理

### 直连就够（国内任务的主路）

| 源 | 备注 |
|---|---|
| 高德卫星瓦片 `webst0{1-4}.is.autonavi.com` | `tiles.py` 默认源，免 key，最新最清晰 |
| 高德路网瓦片 `webrd01.is.autonavi.com` | `style=8`，判路网/城区用 |
| 百度全景 `mapsv0.bdimg.com` | 国内街景主力，免 key |
| 百度识图 `graph.baidu.com` | 中文内容覆盖最好 |
| 360 POI `restapi.map.so.com` | 免 key，小区/楼盘/店铺覆盖好 |
| AWS Terrain Tiles `s3.amazonaws.com` | 高程切片，全球 30 m |
| 必应国内版、搜狗图片 | 关键词/文字/图片搜索 |
| `hf-mirror.com`、`modelscope.cn` | 模型下载镜像（`hf_sources.py` 自动选） |

### 需要代理

| 源 | 少了它会怎样 |
|---|---|
| Google 卫星 `mt1.google.com` | 历史影像更全、19 级更锐；用高德替代也够 |
| Google 街景（`gsv.py`） | 国外为主；国内用 `baidu_pano.py` |
| OSM Overpass（`osm.py` `gazetteer.py`） | 改用 `poi.py`；`gazetteer` 会退到本地表 |
| Yandex 识图 | 用百度识图，国内内容更全 |

**结论：国内任务（城市/景区/片区级）完全不需要代理。** 缺代理只影响 OSM 要素枚举、
Google 历史影像、国外街景。缺了就往下调精度档位，并在报告里写明缺什么。

## 三、代理怎么配（agent 照这个做）

**核心认知：代理不是"设置一个什么东西"，而是"告诉脚本往哪个地址走"。**
代理是本机已经在运行的程序（Clash / v2rayN / Surge 之类），监听一个端口；
脚本不告诉它走哪就直连（超时），告诉它就走代理出口。

`--proxy` 参数和 `GEO_PROXY` 环境变量原版 skill 就有，**不需要改任何脚本代码**。
需要做的只是让 agent 知道代理在哪。

### 1. 探端口：让 `netcheck.py` 自动找，别问用户

```bash
uv run <skill>/scripts/netcheck.py
```

它按优先级收集候选：① 系统代理（macOS `scutil --proxy`，图形界面开的代理软件
在这里生效）→ ② 环境变量 → ③ 常见端口挨个试（7890 / 7892 / 10808 / 10809 /
6152 / 1080 / 2080 / 8888 / 7897），然后**实测筛选**。

> **为什么要系统代理优先**：环境变量里常有 IDE 或内部服务的代理，
> 那个只在内网有用，连境外站点不通。系统代理才是用户装的代理软件。
> **多个候选都要实测**，不能看到第一个就拿来用——这是实测踩出来的。

手动查的话：

```bash
scutil --proxy | grep -iE "Proxy|Port"    # macOS
reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v ProxyServer   # Windows
env | grep -i proxy                        # Linux
```

### 2. 每条命令都带 export

**shell 不跨命令保留变量**，这是最容易忘的一步：

```bash
export GEO_PROXY=http://127.0.0.1:<端口> && uv run <skill>/scripts/tiles.py ...
```

想让整个会话继承：写进 agent 的记忆文件（WorkBuddy 是 `~/.workbuddy/MEMORY.md`）。
想永久生效：`echo 'export GEO_PROXY=...' >> ~/.zshrc && source ~/.zshrc`。

**只想让一条命令走代理**：直接给该命令加 `--proxy`，不污染全局。
支持 `--proxy` 的脚本：`osm.py` `gazetteer.py` `tiles.py` `gsv.py` `revimg.py`
`poi.py` `terrain.py` `match.py` `sat_scan.py` `intake.py` `clues.py` `geo.py`

### 3. 协议要写对

- **Clash 的 mixed-port 用 `http://`**（多数人的 Clash 都是这个）
- **纯 socks 端口才用 `socks5h://`**
- 写错协议会连不上，表现为"配了代理也没用"

### 4. 改完必须验证

```bash
uv run <skill>/scripts/netcheck.py
```

看"需要代理的源"那一段是不是变成了 ✓。**别凭感觉。**

### 5. 配好之后

`tiles.py` / `sat_scan.py` 的 `--source auto` 会**优先试 Google**，
所以配了代理就自动解锁 Google 历史影像和更锐利的 19 级瓦片。

### 6. 没有代理、也不想装

按上面那张对照表走国内源即可，结论精度降到「城市 / 景区 / 片区」级，
并在报告里写明缺的是 OSM 枚举与实景比对。

`tiles.py sheet` 是 `sat_scan.py` 的可靠人工替代路径（出带编号和十字的候选点
卫星缩略图，人工核对）—— skill 的设计本来就是"脚本排序 → 人看前几名"，
`sat_scan.py` 只是排序工具。

## 五、踩坑记录

### 1. 高德瓦片的坐标系口径（最容易搞错）

**高德 `appmaptile` 接口的瓦片编号口径是 WGS84，不需要纠偏成 GCJ-02。**

一开始按"高德用火星坐标"的常识做了纠偏，结果标记点偏移 780 m。
验证方法：用路网瓦片对照——纠偏后的号返回 24.6 KB 空白，正确号返回 192 B 有路网。

注意区分：**坐标展示要纠偏（`geo.py convert`），瓦片编号不要纠偏（`tiles.py`）。**
调用 `tiles.py` 一律传 WGS84。

### 2. huggingface_hub 的 endpoint 要改哪个常量

**症状**：`curl` 拉权重完全正常，但 `sat_scan.py` / `match.py` 一直报
"couldn't connect to 'https://huggingface.co'" —— 看着像网络不通，其实是库的问题。

踩了三次才找到正确改法：

| 尝试 | 结果 |
|---|---|
| 设 `os.environ["HF_ENDPOINT"]` | ❌ 无效，import 时已固化 |
| 改 `huggingface_hub.constants.ENDPOINT` | ❌ 无效（1.x） |
| **改 `huggingface_hub.file_download.ENDPOINT`** | ✅ **生效** |

关键在于 `file_download.py` 里写的是 `from .constants import ENDPOINT` ——
**import 时做了值拷贝**，之后改 constants 它根本看不到。必须改使用方模块自己那份。

**正确做法**（`hf_sources._patch_hub()`）：按 `file_download` → `constants`
→ `utils._runtime` → `huggingface_hub` 顺序，把 `ENDPOINT` / `HF_ENDPOINT` /
`HUGGINGFACE_HUB_ENDPOINT` 全部覆盖。多改几个字段没成本，少改一个就全盘失败。

**还必须拉长超时**：`HF_HUB_DOWNLOAD_TIMEOUT` 默认只有 10 秒，大权重下不完
会被报成"连不上"，**误判成网络问题**。已提到 180 秒。

**顺序要求**：`hf_sources.prepare()` 必须在 `import transformers` **之前**调用。
`sat_scan.py` / `match.py` 里 transformers 都是 lazy import，把 `prepare()`
放在模块顶层正好合适。

**顺带**：CLIP 权重文件名是 `pytorch_model.bin`，**没有** `model.safetensors`，
报 404 时先确认文件名。

### 3. 探针通≠ 大文件能下

探针（`HEAD config.json`）返回 200 不代表权重能下完。`hf_sources.py` 因此逐个镜像
真下真失败才换，而不是只靠探针判断。

### 4. uv 锁冲突

并发跑多个 `uv run` 会抢 wheel 锁，报 `is another uv process running?`。
串行跑，或加 `UV_LOCK_TIMEOUT=300`。

### 5. 沙箱里 Chrome 清理被拦

`revimg.py` 最后清理无头 Chrome 临时目录时被沙箱拦（file-delete 拒绝），
但**截图和 JSON 已正常产出**。看产物判断成功，别看退出码。

### 6. 下载类脚本要给足超时

`intake.py` 实测要 16 分钟以上（双引擎以图搜图各 600/900 s 上限 + 首次装依赖）。
超时给 20 分钟或放后台跑。

## 七、以后怎么用

```bash
# 1. 先探网络（必做，10 秒）
uv run <skill>/scripts/netcheck.py

# 2. 要用 Google / Overpass / 街景 → 按探针打印的地址配代理
export GEO_PROXY=http://127.0.0.1:<探针给出的端口>
uv run <skill>/scripts/netcheck.py    # 验证一下

# 3. 然后正常用 skill，卫星图不用管（默认走国内源）
```

**一句话**：国内**不配代理也能干活**（城市/景区/片区级），
配了代理自动解锁 Google 和 OSM 枚举（能到路/楼级）。
代理端口由 `netcheck.py` 帮你从系统里探出来并实测筛选，不用自己记。
